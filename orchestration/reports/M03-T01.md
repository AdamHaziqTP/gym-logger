## 3. Behavior decisions (documented per task)

- **Category representation asymmetry (narrow ambiguity, resolved):** the HTML
  table keeps exactly the five visible columns and encodes categories as
  inline row colors plus a machine-readable `data-gym-category="Arms|…"`
  attribute (HTML has a native color channel). The plain-text table gains a
  leading `Category` column because plain text has none — otherwise highlight
  information would be silently lost in fallback pastes (violating AC-02's
  "preserve highlights/categories in the generated representations").
  Consequence: a plain-text paste shows six tab-separated fields per row.
  Pinned by named tests on both sides; trivially changeable if product
  prefers a different marker.
- **Dark wrapper block:** spec §15.3 warns dark-mode colors must stay readable
  in Notes. The payload wraps everything in an inline-styled dark `<div>` so
  contrast holds IF block backgrounds survive; whether they do is precisely
  what HV-M03-1 measures (light-appearance readability is on the checklist).
  No assumption either way is encoded in code or tests.
- **Export-after-flush ordering:** tapping Copy settles every debounced
  (≤300 ms) and in-flight save first, then reads the record once. Without
  this, an immediate tap after typing would export stale cells. The flush
  path is covered by a dedicated test (type + tap within the debounce window).
- **Failure wording:** only the combined HTML+plain write may show
  `Copied to Notes ✓` (§15.7 verbatim). Plain-only writes always say plain;
  unavailable/denied clipboard says failed. No state can be mistaken for a
  richer success than actually happened (AC-03, §15.6 "do not silently
  switch").
- **`copiedToNotesAt` left unwritten:** spec §15.7 marks it optional/
  informational; persisting it would add a DB write outside this spike's
  minimum scope. The field remains available for a later task.

## 7. Known limitations / payload caveats

1. **Apple Notes compatibility is UNKNOWN and UNCLAIMED.** jsdom cannot
   execute iOS WebKit clipboard semantics; nothing here proves tables, colors,
   or even text formatting survive a real paste. Human gate:
   `orchestration/evidence/HUMAN-VERIFICATION-M03-T01.md`.
2. **TSV fidelity caveat:** cell values containing literal tabs/newlines blur
   the plain-text column boundaries (values are never altered to prevent it —
   §27.6 fidelity wins over alignment). The HTML representation carries such
   content losslessly.
3. **Readability risk if Notes strips backgrounds:** foreground tokens are
   dark-mode colors; on a white Notes surface the near-white `none` rows could
   wash out unless the dark wrapper background survives. Explicitly listed as
   an HV-M03-1 check; an RTF/native strategy (§15.2) remains out of scope.
4. **iOS gesture timing:** the write happens after an IndexedDB read (post-
   flush). Desktop browsers tolerate this within transient-activation
   windows; actual Safari behavior is part of the device gate. If Safari
   rejects late writes, the UI will show the honest failure state rather
   than pretend success.
5. **Physical-iPhone verification was NOT performed; visual acceptance was NOT
   performed. M01 FIX-05 physical checks remain BLOCKED/DEFERRED** on iPhone
   14 Pro Max LAN reachability — untouched and unclaimed by this spike.
6. Out of scope and untouched: PNG export, automatic append, settings, cloud
   sync, analytics, generic sharing, RTF, backup/restore, native packaging,
   highlight taxonomy (five visible categories unchanged).
