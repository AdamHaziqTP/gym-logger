# M03-T01-FIX-03 — make Apple Notes text highlights survive rich table paste

## Context

The target iPhone 14 Pro Max is now using the trusted HTTPS build. The prior
FIX-02 retest confirmed that Apple Notes receives a real editable table and all
session values, but still strips every category text/highlight color. The
product requirement is the Apple Notes-style colored text/highlight treatment,
not merely a machine-readable category attribute or colored web table.

Authoritative mapping from `GYM_LOGGER_SPEC.md` §5.1 and
`src/domain/highlights.ts`:

- Arms → Orange
- Back → Purple
- Chest → Mint
- Delts → Blue
- Legs → Pink
- `none` → unhighlighted/white internal state; no visible `Other` legend item

## Objective

Make the smallest compatible change that gives iOS Apple Notes the best chance
of importing actual text-run foreground and highlight colors inside the native
editable table, without changing the product mapping or table/data behavior.

## Required implementation direction

1. Keep the existing `text/html` + `text/plain` clipboard contract, table
   structure, order, escaping, deterministic output, and plain fallback.
2. Keep the exact five foreground colors from `HIGHLIGHT_TOKENS`.
3. Preserve the current dark Notes-like visual intent, but add an opaque
   Apple-Notes-compatible highlight representation for the text run (do not
   rely only on translucent `rgba(...)` styles). Use a single documented source
   of truth for any opaque equivalents, derived from the locked tokens against
   the dark presentation background.
4. Add conservative legacy-compatible markup alongside inline CSS where it is
   useful to native HTML paste importers: for example `<font color>` for
   foreground text and `bgcolor`/opaque inline `background-color` for the text
   highlight. Do not remove the semantic table or replace it with an image.
5. Apply the representation to the actual cell text, not just `<tr>`/`<td>`.
   `none` rows must have no colored text, highlight, legacy color attributes,
   or wrapper that falsely communicates a category.
6. Do not add RTF/native code, external services, generic sharing, a sixth
   legend item, or a product redesign in this task.

## Automated acceptance criteria

- Existing tests plus new FIX-03 payload tests pass.
- Tests cover all five mappings and every colored text wrapper/cell; they prove
  foreground and opaque highlight tokens are present in the HTML payload.
- Tests prove `none` remains uncolored/unhighlighted and the visible legend is
  still exactly Arms Back Chest Delts Legs.
- Escaping, deterministic order, real table structure, plain fallback, and
  weird free-form values remain covered.
- `npm test -- --run --reporter=dot`, `npm run build`, and `git diff --check`
  pass.
- Write `orchestration/reports/M03-T01-FIX-03.md`. Do not claim Apple Notes
  acceptance; the iPhone retest remains Codex's human gate.

## Human-gate boundary

After Codex independently verifies the correction, retest on the trusted URL
with the iPhone 14 Pro Max. Paste once into Apple Notes and record separately:

- real editable table and all values/order;
- foreground text colors by category;
- text highlight/background colors by category;
- readability in light and dark Notes appearance.

If Apple Notes still strips colors, record that as platform evidence and stop
for the next product/technical decision. Do not silently accept plain text or
uncolored rich paste as satisfying the requirement.
