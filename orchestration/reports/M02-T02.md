## 4. Today-session conflict behavior (documented per original AC-05)

Chosen behavior (covered by tests, implemented in `CopySession.tsx` + `startTodayFromSession`):

- When no session exists for the target local date, `Use This Session` clones immediately and opens the new session.
- When a session **already exists** for the target date, the tap does **not** write anything: an explicit confirmation dialog appears — title `Replace today's session?`, message naming both dates ("A session for Monday 24 Aug already exists. Use This Session replaces it with a fresh copy of Friday 21 Aug. Your Apple Notes archive is not affected."), actions `Cancel` and `Replace Today's Session`.
- `Cancel` (or backdrop tap) dismisses and leaves every record untouched.
- Confirming **replaces** the existing same-date session rather than creating a second one — the one-session-per-local-date model (§4.1, §27.1) holds even in this non-normal path, so silent duplication is impossible both in UI (fresh existence check drives the warning; double-tap guard) and in data (transactional re-check/delete/write).
- Exact dialog text is asserted verbatim in `copyFlow.test.tsx`.
